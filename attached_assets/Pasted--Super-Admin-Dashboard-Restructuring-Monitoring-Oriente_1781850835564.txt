# Super Admin Dashboard Restructuring & Monitoring-Oriented Architecture

**مهمه لارښوونه:**
دا بدلونونه باید په ډېر احتیاط سره ترسره شي. د سیستم موجوده Database، Backend Logic، APIs، Permissions، User Roles، Business Rules او موجود فعالیتونه باید هېڅ ډول زیان ونه ویني. یوازې د Super Admin Interface، Navigation Structure او Dashboard Experience باید اصلاح او ساده شي.

---

# اصلي هدف

زه نه غواړم چې Super Admin د عادي کاروونکو په څېر ورځني عملیاتي کارونه ترسره کړي.

Super Admin باید د:

* Supervisor
* Controller
* Monitor
* Decision Maker

په توګه عمل وکړي.

هغه باید د سیستم د ټولو کارمندانو، عملیاتو او فعالیتونو څارنه وکړي، نه دا چې د هغوی پر ځای کارونه ترسره کړي.

نو ځکه د Super Admin انٹرفېس باید له Data Entry System څخه Executive Monitoring Dashboard ته واوړي.

هدف:

**Super Admin = Monitoring + Control + Oversight + Analytics**

نه:

**Super Admin = Operational User**

---

# 1. د موجودۍ (Inventory) برخه

اوسني ټول فرعي Menuګانې چې د موجودۍ پورې تړاو لري باید له Navigation څخه لرې او په یوه واحد Menu کې مدغم شي:

## موجودي (Inventory)

کله چې Super Admin پر دې Menu کلیک وکړي، نو باید لاندې معلومات د مناسبو Dashboards، Graphs، Charts، KPIs او Tables په بڼه وویني:

### عمومي موجودي

* د موجودۍ عمومي وضعیت
* د اجناسو ټول شمېر
* د فعالو اجناسو شمېر
* د کمېدونکي سټاک شمېر
* د ختمېدونکي سټاک شمېر
* د ګدامونو وضعیت

### د اجناسو لیست

* نوي اضافه شوي اجناس
* وروستي ثبت شوي اجناس
* د اجناسو کټګورۍ

### د اجناسو داخلې او خارجې

* داخل شوي اجناس
* خارج شوي اجناس
* د داخلېدو او خارجېدو احصایې
* د وخت له مخې حرکت

### راکړه ورکړه

* ټول Transactions
* وروستي فعالیتونه
* د فعالیتونو Trend Analysis

### بارکوډونه

* چاپ شوي بارکوډونه
* د کومو اجناسو لپاره چاپ شوي
* د چاپ تاریخچه

### چیک لیست

* د موجودۍ د چیک لیست وضعیت
* بشپړ شوي موارد
* نیمګړي موارد

### مهم شرط

Super Admin باید د دې برخې له لارې:

* اجناس ثبت نه کړي
* اجناس حذف نه کړي
* اجناس تعدیل نه کړي
* سټاک داخل نه کړي
* سټاک خارج نه کړي

بلکې یوازې معلومات مشاهده او تحلیل کړي.

# 12. د Dashboardونو او Graphونو د اعتبار شرط

دا یو اجباري او حیاتي شرط دی.

ټول:

* Dashboards
* Charts
* Graphs
* KPIs
* Statistics
* Tables
* Summary Cards

باید یوازې د سیستم له حقیقي معلوماتو (Real Data) څخه تولید شي.

هیڅ Dashboard Element باید:

* Dummy Data
* Static Data
* Placeholder Data
* Fake Statistics
* Artificial Metrics
* Generated Numbers

ونه کاروي.

که معلومات موجود نه وي نو باید:

* No Data Available
* No Activity Recorded Yet
* Waiting For Data
* Empty State

وښودل شي.

---

# 13. د بې ضرورته Graphونو او Dashboardونو مخنیوی

AI باید هېڅ داسې:

* Chart
* Graph
* KPI
* Dashboard Widget
* Statistic
* Counter
* Summary Card

جوړ نه کړي چې د سیستم له حقیقي فعالیتونو سره مستقیمه اړیکه ونه لري.

یعنې:

هر Graph، Chart او Dashboard باید د یوزرانو د حقیقي کارونو او ثبت شویو عملیاتو له امله رامنځته شي.

د مثال په ډول:

* که Transaction نه وي ثبت شوی → Graph باید خالي وي.
* که Barcode نه وي چاپ شوی → Barcode Statistics باید خالي وي.
* که Receiving نه وي ترسره شوی → Receiving Dashboard باید خالي وي.
* که Request نه وي ثبت شوې → Request Statistics باید خالي وي.

هیڅ نمایشي، اضافي، پالتو یا مصنوعي Graph او Dashboard مه جوړوه.

وي.

# وروستی شرط

د موجوده سیستم هېڅ Business Logic، Database Structure، API Integration، User Permissions او Workflow ته زیان مه رسوه.

یوازې Navigation، Dashboard Experience او Monitoring Architecture اصلاح کړه.

هدف دا دی چې Super Admin د سیستم د ټولو کارمندانو او فعالیتونو ناظر وي، نه دا چې د هر یوزر کارونه په خپله ترسره کړي.
