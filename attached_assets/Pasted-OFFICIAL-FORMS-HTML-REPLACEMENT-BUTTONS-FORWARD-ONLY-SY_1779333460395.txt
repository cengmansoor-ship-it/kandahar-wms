OFFICIAL FORMS FORWARD-ONLY CASCADING SYNCHRONIZATION
────────────────────────────

Restore and preserve forward-only synchronization.

Workflow order:

const formOrder = [
"proposal",
"tender",
"comparison",
"purchaseOrder",
"receiptReport",
"si9",
"fs5"
];

If the project uses pc5 instead of fs5, support both safely:
const formKeyAliases = {
pc5: "fs5",
fs5: "fs5"
};

Core rule:
Data moves only forward.
Data must never move backward.

When a form is saved:
• that form saves its own data
• shared data goes only to downstream forms
• previous/upstream forms must not change

Mandatory protection:
Before syncing to any target form:

if (targetIndex <= sourceIndex) {
return;
}

Required behavior:
1. Saving Proposal updates Tender, Comparison, Purchase Order, Receipt Report, SI9, FS5.
2. Saving Tender updates Comparison, Purchase Order, Receipt Report, SI9, FS5, but never Proposal.
3. Saving Comparison updates Purchase Order, Receipt Report, SI9, FS5, but never Proposal or Tender.
4. Saving Purchase Order updates Receipt Report, SI9, FS5, but never Proposal, Tender, or Comparison.
5. Saving Receipt Report updates SI9 and FS5 only.
6. Saving SI9 updates FS5 only.
7. Saving FS5 saves itself only and never updates previous forms.

Example:
Proposal quantity = 4 and save:
• Proposal remains 4
• all downstream forms become 4

Tender changes quantity to 3 and save:
• Proposal remains 4
• Tender becomes 3
• Comparison, Purchase Order, Receipt Report, SI9, FS5 become 3

Comparison changes quantity to 1 and save:
• Proposal remains 4
• Tender remains 3
• Comparison becomes 1
• Purchase Order, Receipt Report, SI9, FS5 become 1
